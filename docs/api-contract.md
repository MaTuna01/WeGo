# WeGo 앱 API 계약

앱(iOS)과 Spring 서버가 주고받는 요청과 응답의 모양이다. 서버는 이 문서에 맞춰 구현하고, 앱은 이 문서대로 디코딩한다.

## 원칙

- 앱은 이 서버하고만 통신한다. 공공 API, 경로 엔진은 서버만 호출한다.
- 출시 후에는 하위 호환으로만 바꾼다. 응답 필드는 추가만 하고, 이름이나 의미를 바꿔야 하면 확장 -> 전환 -> 정리 순서로 진행한다.
- 앱은 모르는 필드를 무시한다. 서버는 새 필드를 추가해도 구버전 앱이 깨지지 않는다고 가정해도 된다.
- 문자열 enum 값은 앱이 모르는 값이면 unknown으로 받는다. 서버는 enum 값을 추가할 수 있다.
- 주소는 HTTPS 도메인만 쓴다(IP 금지). 서버를 옮겨도 앱 업데이트 없이 DNS만 바꾼다.

## 공통

### 요청 헤더

| 헤더 | 값 | 설명 |
|---|---|---|
| X-App-Version | 1.0.0 | 앱 버전(CFBundleShortVersionString). 모든 요청에 보낸다. 서버는 로그에 남긴다. |
| Accept | application/json | |

### 오류 응답

2xx가 아닌 응답은 application/problem+json(RFC 9457, Spring ProblemDetail) 형식이다. 앱은 본문을 해석하지 않고 실패로만 처리한다.

    {
      "type": "about:blank",
      "title": "Not Found",
      "status": 404,
      "detail": "...",
      "instance": "/stations"
    }

## GET /app/config

앱 시작 때 한 번 읽는다. 인증 없음.

응답 200

    {
      "minimumVersion": "1.0.0"
    }

| 필드 | 타입 | 설명 |
|---|---|---|
| minimumVersion | string | 최소 지원 버전(major.minor.patch). 앱 버전이 이보다 낮으면 업데이트 안내로 앱 사용을 막는다. |

- 버전 비교는 점으로 나눈 숫자를 앞에서부터 비교한다. 빠진 자리는 0으로 본다(1.2 = 1.2.0).
- 앱은 네트워크 실패, 타임아웃, 2xx가 아닌 응답, 디코딩 실패 때 막지 않고 진행한다. 서버 장애로 앱 전체가 멈추면 안 되기 때문이다.

## GET /stations

공유자전거 정류장 목록. 인증 없음. 1.0은 따릉이만 내려준다.

요청 헤더(선택)

| 헤더 | 설명 |
|---|---|
| If-None-Match | 지난 응답의 ETag. 바뀐 게 없으면 서버는 본문 없이 304를 준다. |

응답 200 (ETag 헤더 포함)

    {
      "stations": [
        {
          "id": "ST-1234",
          "name": "여의나루역 1번출구 앞",
          "operator": "ttareungyi",
          "latitude": 37.5271,
          "longitude": 126.9329,
          "dockCount": 15
        }
      ]
    }

| 필드 | 타입 | 설명 |
|---|---|---|
| id | string | 정류장 ID. 운영사 안에서 고유하고 바뀌지 않는다. 주행 기록이 이 값을 저장하므로 서버는 같은 정류장에 같은 ID를 유지해야 한다. |
| name | string | 정류장 이름 |
| operator | string | ttareungyi(서울 따릉이), tashu(대전 타슈). 앱이 모르는 값이면 unknown으로 받고 그 정류장은 표시하지 않는다. |
| latitude | number | WGS84 위도 |
| longitude | number | WGS84 경도 |
| dockCount | number | 거치대 수. 모르면 생략하거나 null |

- 잔여 대수는 1.0에서 내려주지 않는다. 나중에 추가할 때는 갱신 시각 필드와 함께 추가한다(앱은 참고값으로만 표시).
- 앱은 좌표가 범위를 벗어나거나 (0, 0)인 정류장을 버린다.

응답 304: 본문 없음. 앱은 저장해 둔 목록을 계속 쓴다.

### 앱의 조회 정책

- 순서: 서버 -> 기기 저장본 -> 앱 내장 목록.
- 마지막으로 서버에 확인한 지 1시간이 지나지 않았으면 다시 묻지 않는다.
- 서버 실패 때는 기기 저장본을, 저장본도 없으면 앱 내장 목록을 쓴다.
